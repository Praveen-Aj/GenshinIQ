# GenshinIQ — Comprehensive Audit Findings & Known Issues

**Audit Date:** 2026-09-07  
**Classification:** P0 (Blockers & Integrity Violations), P1 (Architectural & Provenance), P2 (Enhancements & Future Capabilities)

---

## 1. P0 Findings (Critical Data Integrity & Truth Violations)

### P0-1: 62 out of 89 Characters (70%) Have Fabricated Placeholder Base Stats
- **Location:** `data/processed/game_data/characters.json`
- **Issue:** 62 characters have hardcoded dummy values:
  - `base_atk_lvl90: 250.0`
  - `base_hp_lvl90: 11000.0`
  - `base_def_lvl90: 700.0`
  - `ascension_stat: "CRIT Rate"`
  - `ascension_stat_val_lvl90: "19.2%"`
- **Impact:** Gross violation of Core Principle 6 ("Missing data must never become fake data") and Principle 1 ("Structured data beats LLM memory"). Build reviews and stat comparisons for these characters are completely inaccurate.

### P0-2: 163 out of 184 Weapons (88.5%) Have Estimated Stats and Missing Refinements
- **Location:** `data/processed/game_data/weapons.json`
- **Issue:** Generated by `scripts/repopulate_game_data.py` with generic rarity-bracket stats (e.g. 5★ = 608 ATK, 4★ = 510 ATK) and completely empty `refinements: []` and `ascension_materials: []`.
- **Impact:** Prevents accurate weapon comparisons, refinement calculations, and ascension farming planning.

### P0-3: Duplicate IDs Causing Silent Entity Overwrites
- **Location:** `data/processed/game_data/characters.json` and `weapons.json`
- **Collisions Found:**
  - Character ID `10000047`: Shared by **Kaedehara Kazuha** and **Kamisato Ayaka**. Lookups by ID overwrite Ayaka with Kazuha.
  - Weapon ID `14512`: Shared by **Tome of the Eternal Flow** and **Lost Prayer to the Sacred Winds**.
  - Weapon ID `13501`: Shared by **Staff of Homa** and **Calamity Queller**.
  - Weapon ID `11509`: Shared by **Mistsplitter Reforged** and **Freedom-Sworn**.
- **Impact:** Memory indices in `StructuredGameDataProvider` overwrite high-tier 5-star weapons and characters, returning the wrong entity on lookup.

### P0-4: Extremely Incomplete Materials Catalog (Only 6 Items)
- **Location:** `data/processed/game_data/materials.json`
- **Issue:** The entire game materials database consists of only 6 items (Agnidus Agate, Fragment of a Golden Melody, Rainbow Rose, Silken Feather, Philosophies of Order, Philosophies of Justice).
- **Impact:** Blocks ascension planning, weapon leveling calculations, and daily domain farming planner.

### P0-5: Randomized Hashing and Unsafe Fallbacks in Ingestion Script
- **Location:** `scripts/repopulate_game_data.py`
- **Issue:** 
  - Generates persistent IDs using randomized Python `hash(name) % 1000`, causing ID instability across interpreter restarts.
  - Defaults unknown elements to `"Pyro"` and unknown weapon types to `"Sword"`.
- **Impact:** Pollutes data layer with non-deterministic IDs and fake element/weapon assignments.

### P0-6: Unsafe Default Values for Missing Account Data
- **Location:** `backend/models/account.py` and `backend/providers/enka_client.py`
- **Issue:**
  - `crit_rate: float = 0.05`
  - `crit_dmg: float = 0.50`
  - `energy_recharge: float = 1.00`
  - `fetter_level: int = 10`
  - `rolls: int = 1`
- **Impact:** An uninspected or unequipped substat roll silently becomes an actual value rather than `None` / quarantined.

## 2. P1 Findings (Architectural, Provenance & Routing Deficiencies)

### P1-1: Misleading Source Authority Tiers
- **Location:** `data/knowledge/wiki_*.json`
- **Issue:** 94 documents generated from Fandom community wiki are tagged as `AUTHORITATIVE` (Tier 1) rather than `COMMUNITY` (Tier 5).
- **Impact:** Violates Principle 3 (Source Hierarchy). Misleads users into believing community summaries are official HoYoverse declarations.

### P1-2: Frontend Hard-Coded Domain Rotation & Character Icons
- **Location:** `frontend/app.js` (`ROTATION_SCHEDULE`, `CHARACTER_ICONS`)
- **Issue:** The daily farming schedule and avatar mappings are hardcoded in client-side JavaScript instead of being served from canonical backend data models.
- **Impact:** Any new character or domain change requires frontend code edits; disconnects farming planner from actual material requirements.

### P1-3: Binary Chat Query Classification
- **Location:** `backend/services/rag_service.py` (`_classify_query`)
- **Issue:** Query intent is classified as either `general` or `account` via regex.
- **Impact:** Cannot route complex multi-intent questions (e.g. `ACCOUNT_BUILD + WEAPON_COMPARE` or `FARMING + PLANNING`) to dedicated tools.

### P1-4: Absence of Deterministic Calculation Engine
- **Location:** `backend/services/`
- **Issue:** The application delegates build evaluation, stat totals, and damage mechanics entirely to Gemini LLM prompts rather than calculating them in Python code.
- **Impact:** Violates Principle 2 ("Deterministic calculations beat LLM arithmetic"). Artifact CV, main-stat correctness, and substat roll efficiency are not computed deterministically.

### P1-5: Fragile Game Version Tracking
- **Location:** `backend/services/rag_service.py` (`_get_latest_game_version`)
- **Issue:** Game version is inferred by scanning `game_version` strings across all local knowledge files and taking the highest version found.
- **Impact:** Violates Principle 4. A single typo in a document (e.g. "6.0") causes the system to claim a future unreleased patch is current.

### P1-6: Security & API Key Exposure in Local `.env`
- **Location:** `.env`
- **Issue:** Local `.env` contains an active Gemini API key. Although `.gitignore` correctly ignores `.env`, standard rotation and safety validation must be verified.

## 3. P2 Findings (User Experience, Optimization & Future Extensibility)

### P2-1: Lack of Standardized Account Import (GOOD Format)
- **Location:** `backend/services/account_service.py`
- **Issue:** Only Enka public showcase is supported. Full player inventory (weapons, unequipped artifacts) cannot be imported.
- **Impact:** Limits optimizer capabilities to the 8–12 characters in the player's active showcase.

### P2-2: System Health Lacks Developer Observability Metrics
- **Location:** `backend/services/provenance_service.py` & System Health Tab
- **Issue:** Does not report duplicate ID counts, placeholder record counts, API reachability latencies, or Knowledge Gap logs.

### P2-3: Action Buttons are Pseudo-Actions
- **Location:** `frontend/app.js` (`[Ask Teams]`, `⚡ Optimize`)
- **Issue:** Buttons merely pre-fill the chat input bar with a prompt string rather than triggering structured calculation/optimization endpoints.
- **Impact:** Fails Principle 3 of workspace rules ("Zero Dead Placeholders").
